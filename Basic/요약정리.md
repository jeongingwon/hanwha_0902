## 1. Python 기본 문법

### 1-1. Type (자료형)
- **기본 자료형**: `int`, `float`, `str`, `bool`, `complex`
- **컬렉션 자료형**:
  - `list` — 순서 O, 변경 O(mutable), `[]`
  - `tuple` — 순서 O, 변경 X(immutable), `()`
  - `dict` — key-value, 순서 O(3.7+), `{}`
  - `set` — 순서 X, 중복 X, `{}` or `set()`
- **타입 확인/변환**: `type(x)`, `isinstance(x, int)`, `int()`, `str()`, `float()`, `list()`
- **동적 타이핑**: 변수 선언 시 타입 명시 불필요 (실행 중 타입 결정)

```python
x = 10          # int
x = "10"        # str로 재할당 가능
print(type(x))  # <class 'str'>
```

### 1-2. 제어문 - break
- **break**: 반복문(for, while)을 즉시 종료
- **continue**: 현재 반복만 건너뛰고 다음 반복으로
- **for-else / while-else**: break 없이 반복이 끝나면 else 블록 실행 (break로 종료되면 else 스킵)

```python
for i in range(10):
    if i == 5:
        break   # i=5에서 반복문 완전히 탈출
    print(i)
else:
    print("정상 종료")  # break로 빠져나왔으므로 실행 안 됨
```

> **핵심 포인트**: `break`는 가장 안쪽 반복문만 탈출한다(중첩 for문이면 바깥 for문은 계속 돎). 중첩 반복문 전체를 탈출하려면 flag 변수나 함수화가 필요.

## 2. 클래스 예외 처리

### 2-1. 클래스 초기화 (`__init__`)
- 객체 생성 시 자동 호출되는 생성자 메서드
- `self`는 인스턴스 자신을 가리킴 (첫 번째 매개변수, 관례상 self)

```python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

p = Person("Kim", 25)
```

### 2-2. 예외 처리 구문 (try-except)
```python
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"에러 발생: {e}")
except (TypeError, ValueError) as e:   # 여러 예외 동시 처리
    print(e)
else:
    print("예외 없을 때 실행")
finally:
    print("항상 실행 (자원 정리 등)")
```

- **커스텀 예외 클래스**: `Exception`을 상속받아 직접 정의 가능
```python
class MyError(Exception):
    def __init__(self, message="사용자 정의 오류"):
        self.message = message
        super().__init__(self.message)   # 부모 클래스 초기화 필수

try:
    raise MyError("값이 잘못되었습니다")
except MyError as e:
    print(e)
```

> **핵심 포인트**: 커스텀 예외는 `__init__`에서 `super().__init__()`을 호출해 부모(Exception)의 초기화도 함께 수행해야 정상 동작.

## 3. Numpy 특성값 (배열 통계 함수)

| 함수 | 설명 |
|---|---|
| `np.mean()` | 평균 |
| `np.median()` | 중앙값 |

## 5. Pydantic BaseModel - 데이터 검증

- `BaseModel`을 상속하면 **타입 힌트 기반으로 자동 검증**
- 잘못된 타입이 들어오면 `ValidationError` 발생

```python
from pydantic import BaseModel, Field, field_validator

class User(BaseModel):
    name: str
    age: int
    email: str = Field(..., min_length=5)

    @field_validator("age")
    @classmethod
    def check_age(cls, v):
        if v < 0:
            raise ValueError("나이는 음수일 수 없습니다")
        return v

user = User(name="Kim", age=25, email="a@a.com")   # 자동 검증
```

**검증 방법 요약**:
1. **타입 힌트**로 기본 타입 자동 검증 (`str`, `int` 등이 안 맞으면 에러)
2. **Field()**로 제약 조건 추가 (min_length, gt, le 등)
3. **field_validator / model_validator**로 커스텀 검증 로직 작성
4. 검증 실패 시 `ValidationError` 발생 → try-except로 처리 가능

## 6. FastAPI RESTful API - HTTP 상태 코드

| 코드 | 의미 | 상황 |
|---|---|---|
| **200** OK | 성공 | GET 요청 성공 |
| **201** Created | 생성 성공 | POST로 리소스 생성 |
| **204** No Content | 성공, 본문 없음 | DELETE 성공 |
| **400** Bad Request | 잘못된 요청 | 클라이언트 입력 오류 |
| **401** Unauthorized | 인증 실패 | 로그인/토큰 필요 |
| **403** Forbidden | 권한 없음 | 인증은 됐지만 접근 권한 X |
| **404** Not Found | 리소스 없음 | 잘못된 URL/ID |
| **422** Unprocessable Entity | 검증 오류 | Pydantic 검증 실패 시 FastAPI 기본 응답 |
| **500** Internal Server Error | 서버 오류 | 서버 내부 예외 |

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()

@app.get("/items/{item_id}")
def read_item(item_id: int):
    if item_id not in db:
        raise HTTPException(status_code=404, detail="Item not found")
    return db[item_id]
```

> **핵심 포인트**: FastAPI는 Pydantic 검증 실패 시 자동으로 **422**를 반환한다는 점, POST 성공 시 관례적으로 **201**을 쓴다는 점을 기억.

## 7. FastAPI 심화 기능

- **의존성 주입 (Dependency Injection)**: `Depends()`로 공통 로직(인증, DB 세션) 재사용
```python
from fastapi import Depends

def get_db():
    db = DBSession()
    try:
        yield db
    finally:
        db.close()

@app.get("/users")
def read_users(db=Depends(get_db)):
    return db.query(...)
```

- **미들웨어(Middleware)**: 요청/응답 전후 공통 처리(로깅, CORS 등)
- **CORS 설정**: `CORSMiddleware`로 도메인 간 요청 허용
- **비동기(async/await)**: `async def`로 정의 시 비동기 처리 가능, I/O bound 작업에 유리
- **Path/Query/Body 파라미터 구분**:
  - Path: `/items/{item_id}`
  - Query: `/items?skip=0&limit=10`
  - Body: Pydantic 모델로 받음
- **라우터 분리 (APIRouter)**: 기능별로 엔드포인트를 모듈화

## 8. Streamlit UI 연동 - 데이터 흐름 이해

### 핵심 개념: **Streamlit은 위젯 상호작용마다 스크립트를 처음부터 다시 실행(rerun)**

- `st.session_state`: rerun 되어도 값을 유지하기 위한 상태 저장소 (필수 개념!)
```python
import streamlit as st

if "count" not in st.session_state:
    st.session_state.count = 0

if st.button("증가"):
    st.session_state.count += 1

st.write(st.session_state.count)
```

- **주요 위젯**: `st.button`, `st.text_input`, `st.slider`, `st.selectbox`, `st.file_uploader`
- **데이터 흐름 이해가 필요한 이유**: 버튼 클릭 → 전체 스크립트 재실행 → session_state 없으면 값이 초기화됨 → 사용자가 입력한 값/상태를 유지하려면 반드시 session_state 활용
- **FastAPI + Streamlit 연동 시**: Streamlit(프론트) → `requests.post(url, json=data)` → FastAPI(백엔드) → 응답을 다시 Streamlit에서 렌더링하는 구조 이해 필요

```python
import requests
response = requests.post("http://localhost:8000/predict", json={"text": user_input})
st.write(response.json())
```

## 9. AI Native 애플리케이션 아키텍처

- 기존 앱과 달리 **LLM이 핵심 로직/추론을 담당**하는 구조
- 일반적 구성 요소:
  1. **입력 계층**: 사용자 질의(UI, API)
  2. **Prompt/Context 구성 계층**: LLM에 전달할 입력 설계
  3. **LLM 추론 계층**: 실제 모델 호출 (API 또는 로컬)
  4. **Tool/Function calling 계층**: 외부 API, DB, 검색 등 연동
  5. **후처리/검증 계층**: 출력 파싱, 검증(Pydantic 등), 재시도
  6. **저장/메모리 계층**: 대화 이력, 벡터DB(RAG) 등

> 핵심: 전통적 애플리케이션(규칙 기반 로직)과 달리, **자연어 추론이 애플리케이션의 핵심 의사결정 엔진**이 된다는 점.

## 10. Prompt 설계 (Prompt Engineering)

- **명확성(Clarity)**: 구체적이고 명확한 지시
- **역할 부여(Role/Persona)**: "너는 ~전문가다" 형태로 맥락 설정
- **Few-shot 예시 제공**: 입력-출력 예시를 보여줘 패턴 학습 유도
- **단계적 추론 유도(Chain of Thought)**: "단계별로 생각해봐" 등으로 추론 과정 유도
- **출력 형식 지정**: JSON, 표, 특정 태그 형식 요구
- **제약 조건 명시**: 길이 제한, 금지 사항 등

---

## 11. Context 구성 (Context Engineering)

- LLM에 **어떤 정보를 어떤 순서/형태로 넣어줄지** 설계하는 것
- 구성 요소:
  - **System Prompt**: 전역 지침/역할
  - **대화 이력(History)**: 이전 대화 맥락
  - **검색된 문서(RAG)**: 외부 지식 주입
  - **Tool 결과**: 함수 호출 결과값
  - **User Query**: 현재 질문
- **컨텍스트 윈도우 제한**: 토큰 수 제약 → 불필요한 정보는 요약/제거 필요
- **관련성 높은 정보를 앞/뒤 배치**하는 것이 답변 품질에 영향(Lost in the middle 현상)

## 12. Harness 엔지니어링

- **Harness**: LLM을 감싸서 실제 작업을 수행하게 만드는 **실행 환경/프레임워크**
- 구성 요소:
  - **Tool 정의**: LLM이 호출 가능한 함수/API 목록
  - **Orchestration(오케스트레이션)**: 여러 단계의 LLM 호출/도구 호출을 조율
  - **에러 핸들링 & 재시도 로직**: LLM 출력 실패 시 복구 전략
  - **상태 관리**: 여러 턴에 걸친 작업 상태 유지
  - **가드레일(Guardrail)**: 안전성/정확성 검증 장치
- **목적**: LLM 자체는 확률적 텍스트 생성기일 뿐이므로, 이를 **신뢰할 수 있는 애플리케이션으로 감싸는 엔지니어링**이 harness의 역할
